# 罗盘选品与1688比价

## 默认目标

- 每次总计30款不重复的抖音商品，跨随机类目；不是每类30款。
- 罗盘：商品卡 → 商品榜单 → 商品卡榜，品牌选择“非知名品牌”，价格筛选0–15元。
- 默认采用页面可用的最近完整一天，记录实际榜单日期；用户指定周期时优先使用指定周期。
- 只保存抖音商品链接，不核对、分析或输出抖音售价。0–15元是榜单筛选条件，不据此保证所有SKU售价都小于15元。
- 1688记录匹配规格的单件采购价、起批量、运费与运费目的地。不得把搜索卡片最低价直接认定为同款成本。
- 用户提供类目、数量或条件时覆盖默认值。单纯修改Skill规则时只修改Skill，不自动启动30款采集；用户要求开始或继续选品时执行。

## 类目抽样与采集

1. 从当前页面读取真实可选类目路径，不凭记忆编造类目。优先在不同一级类目下选择可用的末级或可直接查询的类目，避免父子类目重复取样。
2. 将可用类目随机打乱，记录抽样顺序。默认先取6个不同类目，每类取榜单前5个符合筛选条件、未重复的商品；不足5款时从下一个随机类目补足，总计30款。类目池不足6个时按实际可用类目分配，明确披露。随机的是类目，不声称商品是全平台随机样本。
3. 每次切类目后重新确认品牌、价格与榜单时间，等待列表更新。记录类目路径、排名、标题、店铺、商品图和点击商品标题得到的抖音URL。
4. 以真实商品URL中的商品ID去重；同一明显商品不同店铺重复出现时优先换候选，无法确认时标记疑似重复。不要依赖第三方扩展注入的checkbox itemid，它可能与真正点击打开的商品ID不一致。
5. 每完成一款即更新checkpoint，包含类目队列、已采集ID、处理状态、当前TaskSpace和页面信息。继续任务先读checkpoint，再重新确认浏览器当前状态。

## 1688匹配与成本

1. 截取商品本体及包装，避开店铺信息和其他私人内容。上传到1688“以图搜款”，等待搜索结果或新标签真正出现。
2. 对外观、品牌/包装、材质、尺寸/净含量和装数作对照。依次打开最接近的候选，通常最多3个；不足以确认时保留“待核实”，不得强行配对。
3. 从1688商品详情记录实际规格、单价、单位、起批量和供应商。区分配件引流价、单个/多件装、批发阶梯价、代发价及会员/老客条件价。未知字段填“未核实”，不能填0。
4. 运费单列并写明页面目的地。只有同数量、同单位且运费明确时才计算含运费成本；“起”价格的合计也必须标为“起”。不默认包邮，不把采购价称为总经营成本。
5. 匹配状态使用“外观与规格匹配”“疑似同款，待核实”“未找到”。页面匹配不证明品牌授权、真伪或实物质量。
6. 30款指30个源商品；未找到货源的行也保留并明确说明。最终分别报告已核实匹配数量、待核实数量、未找到数量，不能把30条采集记录说成30款已核实货源。

## 输出

输出UTF-8 BOM的results.csv，并在聊天中展示简洁结果表（必要时分批展示）。字段：

`序号,采集时间,榜单日期,类目,榜单排名,商品名称,抖音商品ID,抖音链接,1688链接,供应商,对应规格,采购单价元,计价单位,起批量,运费元,运费目的地,含运费成本元,匹配状态,价格条件与备注,截图路径`

抖音链接和1688链接应可点击。没有可靠货源时保留抖音链接并标记状态，不编造1688链接。每完成5款向用户报告进度和异常；受阻时保存已完成结果并说明实际数量。

## 边界与恢复

- 只执行查询、商品截图、用户指定的1688图搜上传和本地记录。不下单、不加购物车、不铺货、不联系供应商。
- 登录失效、验证码、浏览器权限提示或用户接管时保存进度并按ego指南交还控制，不绕过验证。
- 页面选择器失效时重新观察DOM，修正定位；同一阻塞连续2次无法恢复时保存进度并报告具体阻塞，不无限重试。
- 本Skill是代理执行指南，不是无人值守程序；创建Skill不等于设置定时任务。只有用户明确要求定时运行时才配置自动化。
